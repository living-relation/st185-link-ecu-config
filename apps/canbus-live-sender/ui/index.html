TrackCluster RealDash — CAN Live Sender

Same signal map as the browser-only bench-test tool (apps/canbus-bench-test.html, not modified by this app), but this one actually transmits the RealDash frames (0x3EF–0x3F1) to a connected CAN-USB adapter via python-can so the RealDash dashboard reacts live on the bench.

Auto-detects CANable-class adapters running candleLight/gs_usb firmware (the default for this hardware — same protocol CANgaroo already talks to). Needs the WinUSB driver bound via Zadig first, same one-time step CANgaroo required. COM ports are also listed in case the adapter is reflashed to slcan mode.

Bus settings (fixed, same for every frame)

Bitrate1,000,000 bps (1 Mbit/s)
ID typeStandard / 11‑bit (every ID below is < 0x800)
Frame typeData frame (not RTR)
DLC (data length)8 bytes, always
Byte orderBig‑endian — already baked into the bytes shown

What this covers

0x3EF (50 ms)Target λ, Throttle, TC setting/intervention, Boost map, Cruise, A/C
0x3F0 (100 ms)Fuel/Charge‑IAT/Cabin temps, Engine load, Coolant P, Ethanol, Turbo speed, Trigger errors
0x3F1 (50 ms)G‑force X/Y/Z + 6 extended warning bits (packed in byte 6)

Live send log

Send once transmits the frame's current bytes one time. Send continuously auto-repeats at that frame's documented period (50/100 ms) so RealDash keeps seeing fresh values — link_g4x_realdash.xml sets a 2000 ms frame timeout that forces every value in a frame to its offline reading if the ECU stops broadcasting. "Stop all continuous sends" and Disconnect both halt every running timer. Formulas mirror link_g4x_can_setup.json exactly, inverted to compute the raw wire bytes from the display value you type.
