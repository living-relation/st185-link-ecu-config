Rebuild WheelSpeed per 6.30/6.31/6.35, fix four live-pin-flagged-dead bugs

ST185-WheelSpeed was wrong against Daniel's own rules in four ways and is
rebuilt from scratch in gen_wheelspeed.py:

- wss_fr routed through bulkhead A pins 11/28. 6.31 says no bulkhead for any
  wheel VR sensor. Gone - the cables cross the firewall through a grommet, so
  each screen stays unbroken.
- FL and FR outputs dead-ended at bulkhead dummies and never reached an ECU
  pin at all. They now land A23 and B21.
- The two conditioners were bare ring terminals. They are now the 6.30
  enclosures: 2x shielded input, 1x shielded output, screen carried 360 deg on
  the connector shells across a metal box, PCB isolated.
- The file had no cables, so no shields existed in it. Six shielded cables now.

6.35 added to the plan: binder M8 4-way shieldable panel mounts, 86 6618 1121
00004 female for the inputs and 86 6319 1121 00004 male for the output, on a
diecast box of at least 50x50x30 internal. Male on the output so a sensor lead
cannot be plugged into it. Two isolation rules written down because both fail
silently as "flaky sensor": the box must not touch chassis, and the PCB must
not touch the box. Mask the connector landings before powder coat.

6.36 added: pin assignment stays grouped by function, wiring-table row order is
free, and the mating connector always follows the same order.

Four pins were marked notConnected while carrying a signal. All four are the
same bug - a live pin flagged dead:

- ecu_com C4 is CAN 1 Low (green). Per XTREMEX-IO-TABLE.html the comms port is
  1 GND, 2 unused, 3 CAN 1 High, 4 CAN 1 Low, 5 RS232 TX, 6 RS232 RX. All six
  relabelled from the source table.
- csb3io c4 is the CSB3 CANL screw terminal, with wc_l_csb already landing on
  it. c3/c4 now read CANH/CANL.
- acamp declared 7 cavities in its part but modelled 1.
- mrs_ctrl declared 6 but modelled 3, and the two pins we actually know - pin 2
  speed out, pin 6 relay request - sat in slots 1 and 3, so the drawing
  disagreed with the pin numbers in its own signal text. Rebuilt in pin order
  and w_mrs_e re-pointed to the right cavity.

Tooling, because all four of the above were found by machine and not by eye:

- lint_v09.py now reads cable cores and shields, checks the part invariants
  (cavity count, shell iff hasShell), catches notConnected sitting next to a
  signal or a conductor, and allows a shell only on vrc_* per 6.35.
- verify_rebuild.py now counts cable cores as conductors. It previously read
  only `wires`, so it would have called this entire rebuild a data loss while
  the replacement cores sat right there unexamined. EXPECT_GONE entries now
  name the conductor that took each connection over, and the verifier fails if
  a named replacement does not exist - a mapping, not an excuse.

verify_rebuild.py: 267 conductors before, 262 after, MATCH.
lint_v09.py: clean on all eight files.
