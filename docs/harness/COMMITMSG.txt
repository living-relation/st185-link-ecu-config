Cable parts: 'shielded' boolean, not a 'shield' object

set_document_json rejected the WheelSpeed upload outright:

  cableParts.0  Unrecognized key(s) in object: 'shield'
  cableParts.1  Unrecognized key(s) in object: 'shield'

I had inferred the shape from the connector hasShell/shell pair - if a
connector with a shell needs its part to declare hasShell, a cable with a
shield needs its part to declare a shield. Half right. The part declares it,
but with the boolean 'shielded'. The 'shield' OBJECT belongs to the cable
instance only, where it is the conductor that carries the screen.

Changes:
- fix_cable_parts.py: 'shield' object -> 'shielded': True on all three cable
  parts. Also set twistedWithNext on core 1 of the 2-core part - cab_knock1 is
  a twisted pair and the flag lives on the part, not the instance.
- lint_v09.py: reject a 'shield' key on any cablePart; check a cable's core
  count against its part's core count; check that a cable with a shield points
  at a part marked shielded. Cores align BY POSITION, so a count mismatch is
  the wrong gauge and colour on real copper.
- make_min.py: new. Writes the upload copy of each rebuild file into min/ with
  the whitespace stripped. This was being done by hand, which is how min/ goes
  stale and an upload silently ships the previous revision.
- run_pipeline.bat: new. fix_cable_parts -> layout_633 -> lint_v09 ->
  verify_rebuild -> make_min, stopping on the first failure.
